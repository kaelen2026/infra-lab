# 证件照 Web 应用 — 可执行方案(think 产出,已批准待实施)

> 上游:`DESIGN.md`(office-hours 判断 Build)。本文件是决策完整、无占位符的执行方案。
> 模式:玩家/作品集 · 纯前端零后端 · 仅中国地区证件照。

## Building(做什么)
一个纯浏览器端、零后端的**中国证件照**生成器:上传随手拍 → 浏览器本地抠图 → 人脸自动居中并按规格控制头高占比 → 换标准底色(白/蓝/红)→ 按选定规格导出精确像素/DPI 的成品 → 可排版到 6 寸相纸供冲印。图片全程不离开用户设备。

## Not building(明确范围外)
- ❌ 非中国地区证件规格(美签/申根/护照他国等)——本期不做。
- ❌ 任何服务端 / 账号 / 云存储 / 登录。
- ❌ 美颜、换装、AI 修脸、表情调整。
- ❌ 商用授权(RMBG-1.4 为非商用许可,本项目仅作品集/学习)。
- ❌ 移动端原生 App(响应式 web 即可,不做 PWA 离线封装本期)。

## Approach(选定方案)
纯静态 SPA,管线式处理,每个环节失败都有降级,不让流程卡死。

```
上传图片
   │
   ▼
[1] 抠图  RMBG-1.4 @ transformers.js (WebGPU→WASM)
   │            └─ 失败/无 WebGPU → WASM 兜底;再失败 → 提示换图
   ▼
[2] 人脸定位  MediaPipe FaceLandmarker (468 点)
   │            └─ 无清晰单脸 → 降级为手动框选 + 辅助网格线
   ▼
[3] 合成  Canvas:换底色 + 按 spec 的 headHeightRatio 缩放/居中/留白
   │
   ▼
[4] 导出  按 spec 输出精确 px@DPI(单张)
   │
   └─[L3] 排版  Canvas 拼到 6 寸相纸 → window.print() / 导出 PNG
```

规格库为纯数据驱动(`src/specs/cn.ts`),改规格不改代码。

## 洋葱式分期(每期独立可合并、可 demo,后续期不来也不影响已上线部分)

**L1 — 端到端闭环(先跑通)**
- Vite+React+TS+Tailwind 脚手架;`vite.config` 的 `base: '/id-photo-app/'`(项目页路径,必须)。
- 上传 → RMBG-1.4 抠图(WebGPU+WASM 兜底)→ 换白/蓝/红底 → 导出**固定一种规格(一寸 295×413px@300dpi)**。
- 首屏模型下载进度条 + "本地运行不上传"文案;模型由 transformers.js 默认缓存(浏览器 Cache Storage),二次访问免重下。
- ✅ 合并后即是一个可用、可演示的抠图换底工具。

**L2 — 核心哇点(规格合规)**
- 接入 MediaPipe FaceLandmarker:算下巴↔头顶 → 自动居中 + 按 spec 的 `headHeightRatio` 控制头高占比与头顶留白。
- 多规格库(下方 CN 集合),UI 选规格 → 精确 px@DPI 导出。
- 无清晰单脸时降级手动框选。
- ✅ 合并后即是"懂证件照规格"的完整工具,作品集主卖点到位。

**L3 — 相纸排版打印**
- Canvas 把成品按选定规格平铺到 6 寸相纸(4×6in / 152×102mm @300dpi),自动算行列数 + 裁切线。
- `window.print()` 直出 + 导出排版 PNG。
- ✅ 纯前端闭环,无服务端。

## 规格库(China,起步集合 · 实施时每条核对官方来源)
`headHeightRatio` = 头高占成品高度比例(中国标准多在 ~0.6–0.7,实施时按各规格官方值填)。

| id | 名称 | mm (W×H) | px@300dpi | 默认底色 |
|----|------|----------|-----------|---------|
| cn-1in | 一寸 | 25×35 | 295×413 | 白/蓝/红 |
| cn-2in | 二寸 | 35×49 | 413×579 | 白/蓝/红 |
| cn-small-1in | 小一寸 | 22×32 | 260×378 | 白 |
| cn-id | 居民身份证 | 26×32 | 358×441 | 白 |
| cn-passport | 护照 | 33×48 | 390×567 | 白 |
| cn-visa | 签证(常用) | 33×48 | 390×567 | 白 |

> 每条带 `sourceUrl`;UI 标注"规格仅供参考,正式使用前核对官方要求"。**数据准确性为需人工核对项,见 Unknowns。**

## Key decisions(关键决策 + 理由)
1. **栈 = Vite+React+TS+Tailwind**:作品集受众最广,静态产物直进 GitHub Pages。
2. **抠图 = RMBG-1.4 @ transformers.js,WebGPU+WASM 兜底**:浏览器端最成熟、人像分割好、体积可控;代价是非商用许可(本项目可接受)。
3. **人脸 = MediaPipe FaceLandmarker(468 点)**:Google 维护、纯前端、给到下巴/头顶关键点,这是按头高占比裁切的前提;face-api.js 年久失修被否。
4. **仅中国地区**:规格集合小且可逐条核准,驯服"规格出错=工具没用"的脆弱假设。
5. **部署 = GitHub Pages + Actions 构建,`base:'/id-photo-app/'`**:零成本、与纯前端一致;base 路径现在就定死,不留 404 隐患。

## 依赖清单(全部零密钥、零账号,已确认可达)
- npm 包:`@huggingface/transformers`(v3,含 RMBG-1.4 经 HF CDN 拉取)、`@mediapipe/tasks-vision`、React/Vite/Tailwind 生态。
- 模型权重:RMBG-1.4 与 MediaPipe wasm/model 均由各自 CDN 公开拉取,**无需 API key / token / 账号**。
- 托管:GitHub Pages(已是 `kaelen2026` 下仓库,开 Pages 即可)。
- ⚠️ 无任何外部付费 API、MCP server、第三方 CLI 依赖。

## 测试路径
- **Happy path**:上传清晰正脸 → 抠图干净 → 选一寸+白底 → 导出恰好 295×413px@300dpi,头高占比落在 spec 区间。
- **错误**:① 上传非图片 → 拒绝并提示;② 无 WebGPU 环境 → WASM 兜底仍能出图;③ 检测不到脸 → 降级手动框选,不崩。
- **边界**:超大图(如 6000px)不卡死/不 OOM;侧脸/多脸 → 走降级路径;输入已是透明 PNG → 合成不出黑边;打印排版在 A4/6 寸纸上行列数正确、裁切线对齐。

## Unknowns(明确推迟项,各有归属,不阻塞开工)
- **规格精确像素与 headHeightRatio 的官方取值**:上表 px 为通用实践值,实施 L2 填 `headHeightRatio` 时**逐条核对中国官方/公安部门来源**并写进 `sourceUrl`。归属:L2 实施时。不阻塞 L1。
- **RMBG-1.4 对发丝/浅色背景边缘的精细度**:若实测边缘发虚,L2 可加边缘羽化/描边后处理。归属:L2 实测后决定,非必须。
- **大图内存**:若超大图在低端机 OOM,加上传前 downscale 到合理上限(如长边 ≤2000px)。归属:L1 happy path 跑通后按实测加。

## 保留前提(被挑战后确认)
- 目标是作品集/学习,不验证付费;接受 RMBG-1.4 非商用许可。
- 仅中国地区,以完成度和数据准确性换取覆盖面。
- 纯前端到底,L3 打印不引入服务端。
- 按 L1→L2→L3 顺序构建,任一期停手都留下完整可演示产物。
