# 证件照 Web 应用 — 设计文档(office-hours 产出)

> 判断:**Build**(玩家/作品集模式)
> 产出于 office-hours 逼问,供后续 `/think` 出可执行方案使用。**不含实现步骤。**

## 问题陈述
做一个**纯浏览器端、零后端**的证件照 web 应用:用户上传随手拍,自动抠图 → 换标准底色 → 按规格输出精确尺寸 → 排版到相纸供冲印。抠图本身不是难点(模型一跑即出);价值和"哇"点在后面的**规格合规**链路。

## 目标用户(谁看了会"哇")
- **任何被证件照规格折磨过的人**——即几乎所有人。痛点真实且普遍:随手拍尺寸/底色/留白不合格,跑照相馆又贵又慢。
- **作品集场景的面试官**:哇的不是"会抠图",而是人脸自动定位、规格精确导出、相纸排版这套**完整工程闭环**。

## 为什么值得做(玩家模式)
- 垂直场景给了一个**故事**,比"又一个通用抠图站"强得多。
- 抠图占工程量 <20%,真正的肉在:人脸检测+定位、规格库、尺寸/DPI 精确导出、排版。这是把"作业"变"作品"的地方。
- 纯前端推理(WebGPU/WASM)可白嫖 GitHub Pages 托管,零服务器成本,且"图片不离开设备"是证件照场景下真实的隐私卖点。

## 最酷的版本(锁定)
完整版:抠图 + 换底色 + **人脸检测自动居中** + **多规格库**(一寸/二寸/护照/签证)+ **精确像素/DPI 导出** + **6 寸相纸排版打印**。

## 洋葱式交付顺序(关键约束:每一层都是可 demo 的完整闭环)
1. **L1 最窄闭环**:上传 → 抠图 → 换红/蓝/白底 → 导出一寸照。先把端到端跑通。
2. **L2 核心哇点**:+人脸检测自动居中/留白 + 多规格库 + 精确像素/DPI 导出。
3. **L3 完整**:+6 寸相纸排版,可直接拿去冲印。
> 哪怕停在 L1/L2,手里也是一个完整可演示的作品,不会烂尾。

## 保留的前提(被挑战后确认)
- **目标是学习/好玩/作品集**,不是赚钱——所以不验证付费,只追求"做出来够酷、能 demo、能传播"。
- **垂直选证件照**而非通用抠图,接受范围收窄换取故事性和完成度。
- **要做完整版**,但接受按洋葱式顺序构建以防烂尾。

## 待 /think 阶段定夺(本文档不回答)
- 模型选型:浏览器端 BiRefNet / RMBG via transformers.js 或 ONNX Runtime Web;人脸检测用什么(MediaPipe / face-api)。
- 是否纯前端到底,还是 L3 排版/打印需要任何服务端。
- 规格库的数据来源与准确性(各国证件照尺寸/底色规范)。
- 分发:GitHub Pages 静态托管的可行性确认。
